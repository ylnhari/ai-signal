vLLM v0.25 deletes PagedAttention outright

vLLM's v0.25.0 (2026-07-11) makes Model Runner V2 the default execution path for all dense models and removes the legacy attention implementation entirely — the release notes state flatly: "PagedAttention has been removed... The legacy attention implementation is deleted now that V1/MRv2 backends are the standard path." That's a genuine turning point: the single most famous idea in LLM serving, the one every inference explainer treats as the load-bearing primitive, is gone from the reference implementation. v0.25.1 followed three days later with a launch-blocking TorchCodec import fix and a mixed-dtype allreduce/RMSNorm quant-fusion correctness bug — early-adopter friction is already visible days into the new default path.

SGLang ships a GLM-5.2-focused hardening patch the same week

v0.5.15.post1 is a patch release the maintainers describe as "mostly for GLM 5.2" — fixing DSA model-launch failures on non-CUDA/HIP devices, a FlashInfer dependency break on CUDA 12 images, NaN outputs from FlashInfer's TensorRT-LLM FP4 MoE kernels on long inputs, and GLM-5.2's IndexShare mechanism under both PD-disaggregation and context-parallel setups. Shipping a new open-weight model (GLM sits alongside DeepSeek/Qwen/Kimi as a tracked family) is only half the story — this is the serving-engine hardening that follows a release, arriving the same week vLLM tore out its own core attention path. Read together with the vLLM story above, it's a real signal of how much inference-engine churn is happening in July, not two unrelated patch notes.

Migrating a production AI agent to GPT-5.6: 2.2x faster, 27% cheaper

Ploy (an AI site-builder) swapped its production agent from Claude Opus 4.8 to GPT-5.6 after four months of testing frontier models — the first challenger to actually beat their incumbent. Measured results: pages built 2.2x faster (8min → 3m42s), 27% cheaper per build ($2.22 vs $3.06), visual quality up (0.936 → 0.970), and output tokens roughly halved (17.1K vs 33.0K). What's genuinely new isn't the score, it's the infrastructure gap it exposes: GPT-5.6 fills all optional tool parameters with invented values (causing empty file reads 52–64% of the time until Ploy rewrote the schema to required-but-nullable), and OpenAI's newer prompt-caching model abandoned partial-prefix matching, breaking Anthropic-style org-wide caching assumptions outright. Roughly a third of the initial "failures" were eval-harness bugs, not model capability — a useful caution against raw benchmark comparisons.

Claude Code sends 33k tokens before reading the prompt; OpenCode sends 7k

Systima intercepted API traffic (proxy-level logging, cryptographic audit chain matching EU AI Act Article 12 logging requirements) to compare Claude Code against OpenCode on identical tasks. On a minimal "reply with OK" task, Claude Code burned ~32,800 tokens of system prompt before the user's input even arrived, versus OpenCode's ~6,900 — a 4.7x gap. The sharper finding is cache behavior: OpenCode kept byte-identical request prefixes (one cache write per session), while Claude Code rewrote tens of thousands of cache tokens mid-session repeatedly (53,839 vs 1,003 cache-write tokens on identical work, a 54x gap). Both harnesses completed the same coding tasks correctly, yet Claude Code cost 3.7x more per passing run (268K vs 72K tokens) — a real, measured overhead story rather than a vibes complaint, and directly relevant to anyone (Hari included) running Claude Code as a daily driver.

Benchmarking 15 "E-Waste" GPUs with Modern Workloads

A hobbyist benchmarked 15 discontinued NVIDIA enterprise GPUs (K80, M10, M40, M60, P40, P100, V100, T40) against modern LLM, vision, speech, and 3D-rendering workloads, including multi-GPU scaling and mixed-generation setups. Notable results: the $60–200 V100-16GB tracks the much rarer T40 across most benchmarks, P40 beats P100 for LLM inference (confirming community lore with actual numbers), and the M60 punches well above its ~$50 price on Whisper throughput. Multi-GPU scaling was near-linear on ResNet50 training and hashing workloads with minimal communication overhead, and single-core CPU speed mattered more than core count for latency-sensitive workloads (Whisper, ViT attention). Directly useful to anyone weighing decommissioned enterprise cards for a budget inference box.
