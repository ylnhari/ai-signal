Inkling 2 Mini hits 190 tok/s on one RTX PRO 6000 with vLLM and speculative decoding

Hugging Face let a coding agent tune serving of Thinking Machines' open-weights Inkling 2 Mini (about 26B parameters, 3B active, looped mixture-of-experts) on a single 96 GB RTX PRO 6000. Across 46 valid runs, single-user decode rose from 136 to 190.6 tokens/s (+40%) and 8-user aggregate throughput from about 570 to 716 tokens/s (+26%), using a vLLM nightly build with the model's bundled DSpark drafter. Greedy outputs were identical with and without speculation, and long-context retrieval passed up to 250K tokens. What's new: published serving recipes only covered B200/GB300 (sm100) cards, so this is the first tuned recipe for sm120 workstation GPUs; the figures are Hugging Face's own measurements.

Unsloth adds Inkling 2 Mini fine-tuning: 1.8–3.1x faster, 50% less VRAM

Unsloth v0.1.925-beta supports LoRA/QLoRA fine-tuning of Inkling 2 Mini, which fits on Kaggle's free 2x T4 GPUs at about 26 seconds per step but not on a single 15 GB T4. Fine-tuned models export to GGUF (a 17.5 GB q4_k_m file for llama.cpp) or merged 16-bit; merged 4-bit is not supported. Inkling 2 Small is supported too but needs about 290 GB of GPU memory in 4-bit. The release also fixes a wrong maximum-context setting that made Inkling inference 2–3x slower. Speedups are Unsloth's own claims.

TRL v1.19.0: multi-teacher distillation, Inkling 2 Mini support, 2x faster packed SFT

Hugging Face's TRL library now lets DistillationTrainer take several teacher models, with each example's teacher_id choosing which one scores it, and accepts an environment_factory so agents can be distilled against stateful environments. It adds Inkling 2 Mini support (a LoRA SFT clock-reading example goes from 0% to 87.0% of held-out clocks read to the second in 53 minutes on one H100; needs transformers 5.24.0 or newer). Packed SFT with SDPA attention halves step time on an H100 (2.06 s to 1.02 s for Qwen3-1.7B), and AsyncGRPO packing adds about 28% trained tokens per second. SFTTrainer now also adds the chat template's end-of-turn token as a stop token when a base model lacks it, so fine-tuned models stop generating.

Modaic: TypeSafe's Jev is probably a Qwen3.5-35B-A3B fine-tune

Modaic, a competitor, argues that TypeSafe's Jev "System One" model (trained to output calibrated judgments rather than text) is a fine-tune of the open Qwen3.5-35B-A3B mixture-of-experts model. The evidence is circumstantial: p99 latency stays close to median as inputs grow (consistent with a sparse MoE), Jev's answers on China/Taiwan questions resemble Qwen-derived models per Vals AI, and it answers "Yes" to "Are you Qwen?" 56–64% of the time depending on version. TypeSafe has not confirmed this, and the authors call the identity tests weak evidence on their own.

llama.cpp adds named tool choice for automatic parsers

llama.cpp release b12731 implements named tool choice for the automatic tool-call parsers, adds Qwen3-Coder support, turns parallel tool calls off when a specific tool is named, and adds an allowed-subset tool choice. Eight further builds followed within a day, through b12756 (a CUDA FlashAttention data-loading refactor). Release page unfetchable — link only.
